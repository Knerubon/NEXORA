## Read-only extraction design (proposal; not executed)

1. **Preflight / source custody.** Obtain an explicitly approved non-secret research copy or a separately authorized operator-produced historical export. Record source custodian, provider/broker identity, extraction tool and clean code SHA, source query bounds, available history limits, retrieval UTC, raw timezone units, licensing/use constraints and source authenticity evidence. Do not copy account credentials, account identifiers, production DSNs or full runtime logs. A source name is not proof of provenance.
2. **Adapter boundary.** Core consumes a provider-neutral export interface and capability profile. Operator explicitly supplies instrument binding and requested UTC interval; no inferred symbol, broker, contract, session or volume defaults. Provider implementation may read history from an already running integration node under its own authorization. Permit only reviewed metadata/history calls; block order submission, login/account switching, terminal launch, symbol mutation and runtime startup. Fail closed when required history/side is unavailable. This wave does not authorize that operator run.
3. **Immutable raw capture.** Write once to an isolated research destination with raw response chunks, request receipts, provider ordering/IDs and exact original timestamp representation. Stable chunk boundaries, retry overlap deduplication evidence, page boundary checks and completion receipts distinguish provider truncation from true gaps. Record SHA-256 byte hashes, byte sizes and row counts before normalization; never overwrite raw files or silently drop duplicate/corrupt rows. A journal source is a verified backup with source snapshot hash and consistent WAL/checkpoint acquisition performed by its custodian; extraction opens the copy read-only and streams bounded pages.
4. **Two clocks / normalization.** Record market event UTC, native precision/time unit, provider sequence/tie ordering and separate retrieval time. Historical retrieval time is NOT the original knowledge time. Original `received_at`, where available, is preserved; otherwise declare historical availability semantics explicitly and stop evidence-grade replay until Architect accepts the mapping. Never fake original ingest time. Apply only documented operator-declared time conversion once, preserve native timestamps and offset/DST provenance, segment at contract changes. Do not sort equal timestamps without source tie order or invent provider sequences (an extraction ordinal must be labelled as such).
5. **Bid/ask products.** Preserve both finite positive quote sides per tick and reject crossed quotes. Preserve missing-side status rather than fabricate ask from bid or fill gaps. If bars are required, derive distinct synchronized bid OHLC and ask OHLC from those quotes using declared half-open UTC intervals, timestamp and completed-bar availability semantics; keep tick-to-bar lineage, counts and basis. Never treat a bid bar with a closing ask field as ask OHLC. Feed the strategy only completed information; fills use appropriate sides (long entry ask/exit bid; short entry bid/exit ask). One-sided provider bars cannot satisfy the complete-data gate without a separately reviewed approximation policy, and never silently satisfy it. Core schema additions require ADR/consumer review first.
6. **Capabilities and costs.** Version effective-dated instrument identity, quote currency, profit/account currency conversion series and timestamps, digits, point/tick size, contract/tick-value calculation, lot minimum/step/maximum, filling/execution policy and trading-session calendar. Capture applicable commission schedule incl. units, tiers, round-turn/per-side and currency; financing/swap rates, rollover/triple-day conventions and effective dates; exchange/provider fees; slippage/latency assumption provenance and applicable execution capability constraints. Current symbol metadata does not prove historical capabilities. Unknown/unavailable is explicit and blocks complete-cost evidence. Observed bid/ask spread must not be charged twice on side-aware fills; missing historical spread is never zero. Slippage cannot be selected after validation outcomes; Quant owns the preregistered assumption and sensitivity policy.
7. **Quality and authenticity.** Separate raw and normalized reports: exact counts/bounds; missing bid/ask; duplicates/conflicting identities; nonfinite/nonpositive/crossed prices; timezone/offset anomalies; sequence/order/tie failures; stale/gaps/outages versus declared calendar closures; bar completeness/overlap/OHLC consistency; timestamp/capability-version transitions; provider truncation; conversion-rate and cost coverage. Reconcile export receipts with raw counts and independently verify selected source records through the custodian. Do not repair, interpolate or delete anomalies invisibly. Thresholds and permissible censoring remain Quant/Architect decisions before evaluation.
8. **Holdout-safe custody.** Independent custodian creates the candidate range and split registration before any run touches it. Keep raw/normalized holdout payload inaccessible to evaluator/agents until separate Rin authority. Before unlock expose only integrity counts and first/last times permitted by proposed PR #81, not spread/price distributions, charts or cost estimates derived from holdout. External contract schedules may be captured without inspecting holdout prices. Never regenerate a registry to bypass a lock or relabel source/symbol/timestamps. Preserve prior exposure ledger, including operationally observed data; `real_market` does not mean unseen.
9. **Seal / handoff.** Bundle write-once raw hashes, normalized partition hashes, normalization/code/environment fingerprints, provenance/capability/cost references, quality and exclusion reports, parent/snapshot hashes and the independently reviewed expected manifest hash. Pin registry JSON hash, split-plan hash and registration-record commit separately; no caller-selected replacement registry. Hash a canonical manifest and verify every partition, row count and metadata reference on read. Keep retrieval wall clock outside deterministic payload where appropriate, while preserving it in provenance. Store no secrets. Rerun normalization on the same raw bytes to compare canonical output and validate no input mutation.
